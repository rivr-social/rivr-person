# Wiki

The RIVR wiki documents every **user-facing surface** at click level. Each page
follows the same five-slot template so behavior is described the same way
everywhere:

1. **What it is** — a one-paragraph definition.
2. **Where it lives** — the route(s) and repo file anchors.
3. **Every interaction** — each button, menu, and form, and what it does.
4. **Permissions / gating** — who can see or do it, and what's hidden for whom.
5. **Cross-links** — related surfaces, API/MCP tools, and federation behavior.

<Callout type="note" title="Map, not final product-truth">
  These pages are drafted from the product-surface inventory, the user-capability
  matrix, and the code knowledge graphs, then verified against the live app.
  Where a slot is still thin it is marked <strong>TODO</strong> — treat those as
  leads to verify, not guarantees.
</Callout>
